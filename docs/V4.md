# V4: Customer share pack

After a match, the players get their clips via a QR code on the arena TV. Clemens releases each match's pack with one explicit click on the Publisher's **Sessions & share** page.
This is separate from approving posts for the VRLink accounts, and nothing is ever shared automatically.

![TV mode](v4/tv_mode.jpg)

## Publisher
- **Sessions & share** (`/sessions`):
  - Clips are grouped by `matchId`, one session per match. Every format is included: game replay, IRL, split and reaction.
  - **Bot-hero and rejected clips are never shared.**
  - Each clip has a checkbox. **Release share pack (n clips)** uploads the selected clips and shows the share URL, a QR code, **TV mode** and **Revoke**.
- **TV mode** (`/tv/<packId>`): a full screen with no navigation for the arena TV. It shows the VRLink branding, "Get your clips", a large QR code, "Scan me" and the expiry note.
- **QR codes:** generated as SVG with QRCoder (MIT) on the server, ECC level Q. No CDN.
- **Settings** on the same page:
  - VRLinkWeb base URL;
  - share-pack API key (DPAPI-encrypted in the database, never in plain text);
  - expiry note.
  - Without a base URL and key, packs go to the **local** uploader: `<DataDir>/share/<token>/`, served at `http://localhost:5080/share/<token>`. That is enough for tests and DryRun.
- **Data:** table `SharePacks` (migration `SharePacks`) with status `Uploading|Released|Failed|Revoked`, `ReleasedBy`, `PackId`, `Token`, `ShareUrl`, `ExpiresUtc` and the clip ids.

## Web upload (`HttpShareUploader`, contract = `C:\vr\VRLinkWeb\docs\SHARE_PACKS.md`)
1. `POST {base}/api/share-packs` with `Authorization: Bearer <key>`.
   - The body is `{venue, matchId, title, createdUtc (ISO with Z), clips[{clipId, format, type, title, durationSec, width, height, sizeBytes, sha256}]}`.
   - The response is `201 {packId, token, shareUrl, expiresUtc, uploadsExpireUtc, uploads[]}`.
   - Limits are checked before upload: 1–30 clips and ≤ 50 MB per mp4.
2. Each file is PUT straight to Vercel Blob at `uploads[].video|thumb.url`.
   - **Exactly** the returned headers are sent as request headers: `authorization: Bearer vercel_blob_client_…`, `x-api-version: 11`, `x-content-type`.
   - The body is the raw bytes, with no Content-Type content header.
   - 5xx/429 errors are retried (honouring `Retry-After`, up to 5×).
   - On "Token expired", `POST {packId}/uploads` fetches fresh grants and the upload is retried.
3. `POST {packId}/complete` returns `{shareUrl}`.
   - `409 missing_blobs` / `size_mismatch`: those files are uploaded again and complete is retried (up to 2 rounds).
   - `410`: fail.
4. **Revoke:** `DELETE {packId}`. The web side deletes the blobs; the link expires after 30 days anyway.

## Proof (tests in `tests/Publisher.Tests/SharePackTests.cs`)
- Grouping by match: bot-hero and rejected clips are left out.
- **Nothing is shared without an explicit release:**
  - the whole pipeline (import, check, schedule, publish) creates no pack;
  - a release without a person, with an empty selection, or with a bot-hero clip is refused.
- **Web contract against a fake VRLinkWeb + Vercel Blob server:**
  - Bearer key on the API calls only;
  - create body (sha256, sizeBytes, format, ISO createdUtc);
  - 4 blob PUTs with `x-api-version: 11`, `x-content-type` as a request header, client token, and no content type;
  - complete, then the share URL and expiry are stored;
  - revoke → DELETE, and the session shows no active pack.
- **Recovery:** an expired token triggers a refresh and retry; `409 missing_blobs` triggers a re-upload and a second complete.
- A wrong key (401) leaves the pack `Failed` with the error stored.
- **Local uploader:** files and the completion marker are written; revoke deletes the folder.
- The API key is stored encrypted.
- **QR codes:** a share URL encoded by QRCoder decodes back to the same URL with ZXing.Net (test-only, Apache 2.0).
- **UI smoke (local uploader):**
  - Release → `http://localhost:5081/share/<token>` serves the 3 sample clips with player and download;
  - path traversal returns 404;
  - TV mode renders (screenshot above).
